# netspeed

Консольный инструмент на Python для замера скорости скачивания: делает 10 последовательных
HTTP(S)-запросов к указанному адресу, дожидается полного ответа на каждый и выводит среднее время
запроса, общий объём скачанных данных и скорость.

Без внешних зависимостей — только стандартная библиотека. Нужен **Python 3.10+**
(используется синтаксис аннотаций `float | None`).

## Запуск

```bash
git clone https://github.com/matrixenchant/netspeed-py
cd netspeed-py
python netspeed.py https://proof.ovh.net/files/10Mb.dat
```

Быстрая проверка на встроенной тестовой ссылке (публичный файл OVH на 10 МБ,
`https://proof.ovh.net/files/10Mb.dat`):

```bash
python netspeed.py --test
```

Тесты (unittest, поднимают локальный HTTP-сервер, интернет не нужен):

```bash
python -m unittest -v
```

### Параметры

```
python netspeed.py [-h] [--test] [-n COUNT] [-t TIMEOUT] [--max-time MAX_TIME]
                   [--bust-cache] [--no-progress] [--no-chart] [url]

  url                   адрес для скачивания (http:// или https://)
  --test                использовать встроенную тестовую ссылку вместо url
  -n, --count COUNT     количество запросов (по умолчанию 10)
  -t, --timeout TIMEOUT таймаут одной операции сокета: подключение / каждое чтение, с (по умолчанию 30)
  --max-time MAX_TIME   общий лимит времени на один запрос, с; 0 — без лимита (по умолчанию 120)
  --bust-cache          добавлять к URL ?_=<timestamp>, чтобы CDN не отдавал кеш (ломает подписанные URL)
  --no-progress         отключить live-прогресс-бар
  --no-chart            не печатать график скорости
```

## Пример вывода

Во время скачивания каждого запроса строка обновляется на месте (live-прогресс):


- Прогресс-бар рисуется, только если вывод идёт в терминал. При перенаправлении в файл или пайп
  печатаются только итоговые строки, без мусора из `\r`.
- Если сервер не прислал `Content-Length`, вместо процента показываются скачанный объём и скорость.
- Если консоль не умеет выводить псевдографику (например, cp1251 в пайпе на Windows),
  бары рисуются ASCII-символами `#` и `.`.
- Длина столбца графика пропорциональна скорости запроса, самый быстрый запрос получает полную
  ширину. `overall` в подписи — это итоговая `DOWNLOAD SPEED`, а не среднее по столбцам.

## Тип контента

В сводке выводится, что именно скачивалось: `image`, `video`, `audio`, `HTML page`, `JSON`,
`PDF document`, `archive`, `binary file` и т. д., а в скобках — исходный MIME-тип.

- Тип берётся из заголовка ответа `Content-Type`. Сервер знает, что отдаёт, поэтому заголовок
  важнее расширения в URL (по адресу `/a.jpg` может вернуться HTML-страница с ошибкой).
- Если заголовка нет, тип угадывается по расширению в URL (`mimetypes`), и в выводе это
  помечается как `guessed from URL`.
- Для HTML-страницы выводится предупреждение: скачивается только сам документ, без картинок,
  CSS и JS. Он обычно маленький, поэтому результат отражает задержку, а не ширину канала.

## Единицы измерения

| Величина | Единица |
|----------|---------|
| Скорость | **Мбит/с (Mbit/s)**, десятичные: 1 Мбит = 10⁶ бит, как у провайдеров и speedtest-сервисов. В скобках — МБ/с (MB/s = Mbit/s ÷ 8) |
| Объём    | **МБ (MB)**, десятичные: 1 MB = 10⁶ байт; точное значение в байтах — в скобках |
| Время    | **секунды (s)** |

## Что и как замеряется

- **Время запроса** — от вызова `urlopen` до прочтения последнего байта тела (`time.perf_counter`,
  монотонные часы). Каждый запрос открывает **новое соединение** (keep-alive не используется),
  поэтому время включает DNS, TCP- и TLS-рукопожатие и ожидание ответа сервера.
- **TTFB** (time to first byte) — время до получения заголовков ответа, то есть именно эти накладные
  расходы. Показывается для каждого запроса и в среднем.
- **Объём** — только байты **тела ответа**, без HTTP-заголовков. urllib не запрашивает сжатие
  (`Accept-Encoding: gzip` не отправляется), поэтому посчитанные байты — это реально пришедшие
  по сети данные тела. Если тело пришло не полностью (меньше `Content-Length`), запрос считается
  ошибкой.
- **DOWNLOAD SPEED** (основной результат) = весь скачанный объём / суммарное время запросов ×
  8 / 10⁶. Это «скорость с точки зрения пользователя», вместе с рукопожатиями.
- **Transfer speed** — то же, но из времени вычтен TTFB: скорость передачи самого тела.
  На маленьких файлах разница с `DOWNLOAD SPEED` большая, поэтому для замера берите файл от 10 МБ.
- **Request time / Speed per request** — среднее, минимум, медиана и максимум по успешным
  запросам. Медиана устойчива к одной случайно медленной попытке, которая искажает среднее.
- Ответ читается потоково (`read1`, до 64 КиБ за раз), поэтому большие файлы не держатся в памяти.
- Отправляются `Cache-Control: no-cache` / `Pragma: no-cache`. CDN их часто игнорирует, поэтому есть
  опциональный `--bust-cache`: к URL добавляется уникальный параметр `?_=<timestamp>`. По умолчанию
  он выключен, потому что ломает подписанные URL (S3 presigned и т. п.).
- `--timeout` — это таймаут **каждой операции сокета** (так работает urllib), а не всего запроса:
  сервер, отдающий по байту раз в 29 секунд, его не превысит. Поэтому есть отдельный общий дедлайн
  `--max-time`, который проверяется между чтениями.
- Если отдельный запрос упал (DNS, сеть, HTTP 4xx/5xx, таймаут, обрыв тела, некорректный URL),
  он выводится как ошибка и не учитывается в статистике, остальные запросы продолжаются.

## Коды выхода

| Код   | Значение |
|-------|----------|
| `0`   | все запросы успешны |
| `1`   | все запросы упали |
| `2`   | неверные аргументы (стандартный код argparse) |
| `3`   | часть запросов упала, статистика посчитана по успешным |
| `130` | прервано по Ctrl+C |
